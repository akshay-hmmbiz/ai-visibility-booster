# Frequently Asked Questions — AI Visibility Booster

*Plugin developed by Akshay Bhimani.*

---

## General

### 1. What does AI Visibility Booster actually do?

It makes your WordPress site more readable and indexable by AI systems such as ChatGPT, Claude, Gemini, Perplexity, and Bing AI. It does this through eight features: content summaries, a supplementary AI sitemap, a JSON discovery feed, a knowledge graph, JSON-LD structured data, an AI Visibility Score, a Markdown export endpoint, and a log of AI bot visits. It cannot guarantee that any AI system will crawl or cite your site.

---

### 2. Does this plugin replace my existing SEO plugin (Yoast, RankMath, AIOSEO)?

No. AI Visibility Booster is a complement to, not a replacement for, your SEO plugin. It automatically detects Yoast SEO, RankMath, and AIOSEO and adjusts its output to avoid duplication — for example, it will not output a `<meta name="description">` tag or a `WebSite` JSON-LD block if your SEO plugin already handles those. The AI-specific features (sitemap, feed, knowledge graph, Markdown export) are entirely additive and do not conflict with any SEO plugin.

---

### 3. Will this plugin slow down my website?

It should not be noticeable, but this has not been measured. All three endpoint outputs (sitemap, feed, knowledge graph) are cached via WordPress transients for 12 hours. The caches are invalidated automatically when you save a post. The plugin adds only a few lightweight meta tags and a small JSON-LD block to your page `<head>` — this is a small amount of work per page. When Bot Analytics is on, each request from a known bot also writes one row to the database. The bulk summary generation runs as an AJAX request in the admin.

---

### 4. Does the plugin expose any personal data about my users or authors?

No. By design:
- Author names are excluded from the AI feed (`/ai-feed.json`) and knowledge graph (`/ai-knowledge.json`).
- No visitor data, analytics, or user metadata is included in any endpoint output.
- Password-protected, private and draft posts are left out of every endpoint.
- Bot Analytics logs requests from known bot user agents only. It stores a salted hash of the IP address, not the address itself. The log is visible only to administrators.
- The Article JSON-LD schema uses the Organisation name as the author rather than individual user data, to prevent user enumeration.
- The AI Visibility Score REST API endpoint requires a logged-in user who can edit the requested post.

---

### 5. I installed the plugin but the AI endpoints return 404. How do I fix this?

Go to **Settings → Permalinks** and click **Save Changes**. This flushes WordPress rewrite rules and registers the plugin's custom URL rules. This is the most common cause of 404 errors after activation. If the problem persists, verify that your server's `.htaccess` file (Apache) or `nginx.conf` (Nginx) is configured to pass requests to WordPress's `index.php`.

## AI Content Summaries

### 6. How are summaries generated? Does it use an AI API?

No external AI API is used. Summaries are generated locally on your server by extracting the first non-empty paragraph from the post content, stripping HTML tags, normalising whitespace, and trimming to approximately 200 characters or 35 words. This is fast, free, and works offline. The summaries are stored as `_aivb_summary` post meta and output as `<meta name="ai-summary">` in the page `<head>`.

---

### 7. Can I customise the summary for a specific post?

Not through the plugin UI directly. Summaries are auto-generated from post content and stored as post meta. You can edit the `_aivb_summary` meta field directly with a custom fields plugin or in the database. Be aware that the summary is regenerated every time the post is saved, so a hand-written summary is overwritten on the next save.

---

### 8. The "Bulk Generate Missing Summaries" button does nothing. What's wrong?

Check the following:
1. Your user account must be an Administrator (`manage_options` capability).
2. Open your browser's developer console (F12) and check for JavaScript errors.
3. Confirm that WordPress AJAX is working — visit `wp-admin/admin-ajax.php` and confirm it returns `0` (not a 404 or server error).
4. If you use a security plugin that blocks AJAX requests, whitelist the `aivb_bulk_generate` action.

## AI Sitemap

### 9. Does the AI sitemap replace my existing XML sitemap?

No. The AI sitemap at `/ai-sitemap.xml` is a supplementary, AI-optimised sitemap that coexists with your existing sitemap (generated by Yoast, RankMath, or WordPress core). It uses a custom `<ai-sitemap>` XML format that includes AI-specific fields like `<summary>` and `<category>`. It is tagged with `X-Robots-Tag: noindex` so it does not compete with your regular sitemap in traditional search results.

---

### 10. Should I submit the AI sitemap to Google Search Console?

No. The `X-Robots-Tag: noindex` header intentionally prevents it from being indexed by traditional search engines. It also uses a custom XML format that Search Console would reject. It is meant for AI crawlers and tools that are pointed at it directly. No AI company has said it reads this format.

---

## AI Discovery Feed

### 11. What is the difference between the AI sitemap and the AI Discovery Feed?

The AI sitemap (`/ai-sitemap.xml`) is XML-format and follows a sitemap-like structure. The AI Discovery Feed (`/ai-feed.json`) is JSON-format and includes richer metadata: site-level details (name, description, language), all post summaries, and category/tag arrays per post. JSON is easier for AI systems to parse programmatically. Both serve similar purposes but are optimised for different AI consumers.

---

### 12. The `Access-Control-Allow-Origin: *` header on the feed — is that safe?

Yes. The feed exposes the same content already publicly visible on your website (published post titles, URLs, summaries, and taxonomy terms). There is no sensitive or private data in the feed. The wildcard CORS header is intentional to allow any AI system or automated tool to fetch the feed cross-origin without restriction.

---

## AI Knowledge Graph

### 13. What is the AI Knowledge Graph used for?

The knowledge graph at `/ai-knowledge.json` gives AI systems a high-level map of your site's topics, concepts, navigation, and content relationships. Where the feed lists individual posts, the knowledge graph describes your site's structure: which categories exist, how many posts they contain, what tags you use, and how they relate. It is this plugin's own format. Whether a given AI system reads it is up to that system.

## JSON-LD Structured Data

### 14. The FAQPage schema is not appearing on my post. Why?

FAQPage schema is only auto-generated when the plugin detects FAQ content in your post. It looks for two patterns:

- `<strong>Q: question text?</strong>` followed by `<p>A: answer text</p>`
- An `<h2>`, `<h3>`, or `<h4>` heading that ends with a `?`, followed by a `<p>` answer

Make sure your FAQ content matches one of these formats. If you use a dedicated FAQ plugin or block, its output format may not match these patterns.

---

### 15. I have Yoast SEO installed and the structured data looks duplicated in testing tools. What should I do?

AI Visibility Booster automatically detects Yoast SEO and skips outputting Organization, WebSite, and FAQPage schemas to avoid duplication. Only Article schema is output alongside Yoast's output. If you are seeing duplication, check that `WPSEO_VERSION` is defined (it should be if Yoast is active). You can also disable Structured Data entirely in **AI Visibility → Settings** if you prefer to rely solely on Yoast.

## AI Visibility Score

### 16. My score is 0 even though the post has content. What's wrong?

The score is calculated each time the editor asks for it. Click **↻ Refresh Score** in the Gutenberg sidebar. If it still shows 0, the post content has no headings, links or text the checks can find, which can happen with page builders that store content outside the post body. The REST API endpoint (`/wp-json/aivb/v1/score/{post_id}`) only answers logged-in users who can edit that post.

---

### 17. How do I improve my AI Visibility Score?

The score is based on six criteria. Here is what to focus on:

| Issue | Fix |
|---|---|
| No AI Summary (0/20) | Resave the post — summary is auto-generated |
| Low word count (< 300 words) | Expand the post with more relevant content |
| No H1 heading (0/10) | The check looks for an `<h1>` inside the post content. Most themes already print the title as the page H1, so adding a second one is a judgement call. |
| No H2 subheadings (0/10) | Break content into sections with `<h2>` headings |
| Few internal links (< 5) | Add links to other posts on your site |
| No structured data (0/20) | Enable Structured Data in Settings, or use Yoast/RankMath |

## AI Markdown Export

### 18. What is the Markdown export endpoint used for?

The `/ai-markdown/{slug}` endpoint serves any published post as clean Markdown. Markdown has less noise than HTML (no CSS classes, attributes or page boilerplate), so it is easier for AI tools to read. The converter is basic and handles common elements only. It is also useful for developers building content pipelines.

---

### 19. Can the Markdown endpoint be used to scrape my content?

The endpoint only serves content that is already publicly accessible on your website. It does not expose any content that is not already visible at the post's normal URL. Password-protected, private and draft posts return a 404. The `X-Robots-Tag: noindex` header prevents search engine bots from indexing the Markdown versions. If you need to restrict access, you can disable the Markdown Export feature entirely in **AI Visibility → Settings**.

---

## Compatibility and Conflicts

### 20. Is the plugin compatible with page builders (Elementor, Divi, Beaver Builder)?

The plugin works with any theme or page builder. Summary generation and scoring analyse the stored post content (`post_content`), not the rendered HTML. Some page builders store content as shortcodes or JSON in `post_content`, which may affect summary quality. If a page builder stores content separately (e.g., Elementor), the extracted summary may be shorter or empty. In that case, you can set a custom summary directly via post meta.

---

### 21. Does the plugin work with custom post types?

No. Every feature works with the `post` and `page` post types only. Custom post types are not included in the sitemap, feed, knowledge graph or Markdown export, and do not get a summary or a score box.

---

### 22. Does the plugin work with WordPress Multisite?

It has not been tested on Multisite. Settings, summaries and caches are per site. Activate the plugin on each site separately, because network activation creates the bot log table for the main site only.
